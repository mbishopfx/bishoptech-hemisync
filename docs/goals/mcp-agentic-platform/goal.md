Research the current live Cognistration platform and repository, route the meaningful tone-frequency controls through governed agent contracts, then design, implement, verify, and release one distinctive agentic feature that strengthens the WebMCP challenge submission without weakening consent, privacy, or product truth.

- Input shape: `existing_plan` with an open product-design choice

- Authority: `requested` for implementation and CLI inspection; production proof is evidence-gated per the supplied structure kit

## Non-Negotiable Constraints

- Keep one shared service layer beneath UI, REST, WebMCP, MCP, and later member tools.
- Public MCP starts read-only and evidence-oriented; never expose arbitrary SQL, code execution, secrets, private records, or unrestricted writes.
- Validate input before model/provider calls or writes; bound time, output, cost, and tool calls.
- AI may classify/retrieve/summarize; deterministic code owns permissions, entitlements, pricing, quotas, calculations, and state transitions.
- Starting local audio requires explicit confirmation. Signup and payment require user review and submission.
- Preserve the existing dirty homepage/header work and unrelated parent-checkout edits.
- Preserve current brand, safety language, one-time `$20` offer, and the existing Supabase Auth/Stripe boundary.
- Do not call local build, preview, HTTP 200, or Vercel Ready state production or real-operation proof.
- Treat frequency/state labels as product metadata and listening directions, never diagnoses, treatment, or guaranteed neurological outcomes.
- Derive safe numeric ranges and cross-field constraints from the actual synthesis/rendering implementation; do not invent capabilities the engine cannot honor.
- Keep public composition ephemeral and user-controlled; require authentication, entitlement, ownership, and explicit confirmation for durable generation or playback where the existing platform requires them.
